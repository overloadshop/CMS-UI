# 06 · 统一入口与 分层式分类

组件库的公开调用面按 声明式 的组件体系组织，入口是 `CMS` 对象：

```
CMS
├── Appearance     主题与全局外观
├── Navigation     TabView、胶囊导航、标签导航、顶栏与返回按钮
├── Controls       开关、滑块、菜单、输入框与选择器
├── Content        Pager、Page、ScrollView、HorizontalScrollView、PageView、文本与列表
├── Layout         VStack、HStack、ZStack、Group
├── Interaction    触控优先级、玻璃融合、返回历史
└── Presentation   Alert、ActionSheet、Dialog、Sheet
```

## 一、最小调用

```kotlin
import com.lindicra.cms.CMS
import com.lindicra.cms.CMSSettings
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.pager.rememberPagerState
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import kotlinx.coroutines.launch

@Composable
fun AppPages() {
    CMS.Appearance.Provide(CMSSettings(darkTheme = null)) {
        CMS.Appearance.Theme {
            val pager = rememberPagerState { 2 }
            val scope = rememberCoroutineScope()
            Column(Modifier.fillMaxSize().windowInsetsPadding(WindowInsets.safeDrawing)) {
                CMS.Navigation.CapsuleNavigation(
                    listOf("记录", "工具"), pager.currentPage,
                    { scope.launch { pager.animateScrollToPage(it) } },
                    pageProgress = pager.currentPage + pager.currentPageOffsetFraction
                )
                CMS.Content.Pager(pager, Modifier.weight(1f)) { page ->
                    CMS.Content.Page(topInset = 0.dp, topBarReserve = 12.dp, topBar = {}) {
                        CMS.Content.Text("第 ${page + 1} 页")
                    }
                }
            }
        }
    }
}
```

## 三、形式自适应（系统 思路）

系统的 TabView 会按尺寸类换形态（iPhone 底栏、iPad 侧栏），这里同样默认自适应：

```kotlin
enum class CMSTabForm { Auto, Edge, Floating, Rail }

CMS.Navigation.TabView(..., form = CMSTabForm.Auto)  // 默认
```

| `form` | 行为 |
| --- | --- |
| `Auto` | 窗口宽度 ≥ 600dp → 侧栏 `Rail`；否则贴边底栏 `Edge` |
| `Edge` / `Floating` / `Rail` | 强制指定，用于特殊页面 |

`placement` 仍保留 `Bottom` / `Top`（顶部摆放由宿主处理安全区），默认取全局 `CMSSettings`。

## 四、全局默认与覆盖

`CMSSettings` 字段：`darkTheme`（null 跟随系统）、`accentColor`、`glassMaterial`、
`hapticsEnabled`、`tabPlacement`、`tabForm`。

`CMSDefaults` 提供组合期读取：`darkTheme()`、`accentColor()`、`glassMaterial()`、
`hapticsEnabled()`、`tabPlacement()`、`tabForm()`。

嵌套 `Provide` 时内层覆盖外层，单个组件仍可显式传参覆盖。

## 五、旧命名

旧顶层函数继续可用，统一入口是新接入的推荐调用面。部分高级能力仍在顶层 API 中，例如 GlassButton 的流体轮廓、原生 Pager 适配器和 CMSTabPager。不要在未核对接口的情况下机械替换名称。

## 六、分页与状态归属

| 需求 | 推荐接入 | 宿主持有 |
| --- | --- | --- |
| 一个滚动内容页 | Page | 业务内容、顶栏、系统栏预留 |
| 多个完整页面左右切换 | Pager 内放 Page | PagerState、导航与业务状态 |
| 已有页面外壳 | Pager 内放主 ScrollView | 页面布局与同一 PagerState |
| 图片 / 卡片轮播 | PageView | 轮播数据，内部管理位置 |
| 表格 / 长代码局部横滑 | HorizontalScrollView 或 cmsHorizontalScrollTouchPriority | 横向 ScrollState；自动登记区域并交接纵向桥 |
| 页面内分类导航 | CapsuleNavigation / TabNavigation | selectedIndex 或 PagerState |
| 原生 Pager 保留复杂配置 | cmsPagerTouchPriority | 每页桥、采样边界与专用区域 |

Pager 自动为每页 Page / ScrollView 提供一个主滚动桥和统一采样。默认 `respectConsumedGestures = false`，新按下可打断旧动量并重新判向；专用拖动区域用 canStart 排除。

局部横滑、轮播与滚动条登记自身有效视口，父级在 down 让出整次仲裁；表格和代码横滑时不触发切页，按住转纵滑仍连续送达页面。独立 ScrollView 可接管原生玻璃纵滑。抖动抵消、快速换向与抬手后新会话均属于 TouchPriority。

交互策略不是 CMSSettings 的软件偏好字段。通过 CMS.Interaction.TouchPriority 在需要的组件子树内配置，父级 Pager 与页面继承同一策略。

返回历史也通过作用域接入：`CMS.Interaction.BackHistory(appHistory) { ... }`，内层 `CMS.Appearance.Theme` 默认继承外层接口。宿主管理实际栈，列表不含当前页；完整契约与多级案例见 [返回历史](components/BackHistory.md)。

完整接入见 [集成指南](03-集成指南.md)、[Page](components/Page.md)、[触控优先级](components/TouchPriority.md)。独立组件文档提供参数、默认值、状态与边界表。
