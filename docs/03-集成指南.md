## 0. 统一入口

```kotlin
CMS.Appearance.Provide(CMSSettings(darkTheme = null, tabForm = CMSTabForm.Floating)) {
    CMS.Appearance.Theme {
        // 单页使用 CMS.Content.Page；
        // 完整分页使用 CMS.Content.Pager，见下面的页面接入。
    }
}
```

`CMS` 门面、`CMSSettings` 全局默认与逐组件覆盖规则见
[`06-统一入口与全局配置.md`](06-统一入口与全局配置.md)。旧顶层 `CMS*` 函数仍可用。

## 2. 推荐：库模块接入

**推荐：模块接入。** `cms-core` 统一提供组件、主题、资源与原生桥。
SDK 用 `ANDROID_HOME` 或本地 `local.properties` 指定。
`cms-core` 的 sourceSets 自动包含 `cms/halfmodal/`、主题、资源与 JNI，无需逐个复制。
接入宿主时复制完整 AndroidCMS 目录、注册四个库模块，并依赖 `project(":cms-core")`；
已有源码副本需要先移除，避免同名类型冲突。

保持完整目录，放到宿主 app 同级。无需接入 example 模块。

```text
宿主工程/
├── app/
├── AndroidCMS/
│   ├── cms-core/
│   ├── cms/
│   ├── theme/
│   ├── res/
│   ├── native/
│   └── modules/
└── settings.gradle.kts
```

可选组件 `AndroidCMS/optional/CMPlayerBackground.kt` 依赖 `coil-compose` 与宿主播放器类
（`PlayerViewModel`、`PerformanceGovernor`、`RenderSubsystem`），**按需复制**，不要一起拷。

## 3. 库模块

将 `AndroidCMS/gradle/settings-snippet.gradle.kts` 合并到宿主 settings.gradle.kts；该片段的路径以完整 AndroidCMS 文件夹为前提：

```kotlin
include(":cms-core", ":liquidglass", ":continuous-rounded-corner", ":shared-elements")
project(":cms-core").projectDir = file("AndroidCMS/cms-core")
project(":liquidglass").projectDir = file("AndroidCMS/modules/liquidglass")
project(":continuous-rounded-corner").projectDir = file("AndroidCMS/modules/continuous-rounded-corner")
project(":shared-elements").projectDir = file("AndroidCMS/modules/shared-elements")
```

库模块使用 version catalog 别名，宿主需合并本目录 `gradle/libs.versions.toml` 中的插件和依赖别名。已有同名模块或别名时按实际工程合并，不重复注册。

## 4. 宿主依赖

模块接入在宿主 app 中添加：

```kotlin
dependencies {
    implementation(project(":cms-core"))
    // 使用 ComponentActivity.setContent 时，宿主还需自己的 activity-compose 依赖。
}
```

| 内容 | 模块接入的处理 |
| --- | --- |
| CMS 组件、主题、字体和图标 | cms-core sourceSets 统一引入 |
| Compose、haze、玻璃及圆角模块 | cms-core 定义依赖；宿主按自己的直接使用需求添加依赖 |
| VIBRATE 权限 | 库 manifest 合并 |
| JNI 与原生桥 | cms-core 统一配置 |
| 旧源码副本 | 从宿主编译源中移除，避免重复类 |
| 可选业务组件 | 不参与默认编译，按需单独适配 |

1.1.0 不再需要 haze-blur。模块接入还需要 SDK 36、NDK 27.0.12077973 和 CMake 3.22.1；具体版本以库构建文件为准。

## 5. 主题接入

**方式 A：使用统一 Theme**

```kotlin
setContent {
```


## 6. 推荐页面接入

新建完整页面用 Page，左右分页用 Pager。下面的示例可放在宿主主题内：

```kotlin
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.pager.rememberPagerState
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import com.lindicra.cms.*
import kotlinx.coroutines.launch

@Composable
fun TwoPageContent() {
    val pager = rememberPagerState { 2 }
    val scope = rememberCoroutineScope()
    Column(Modifier.fillMaxSize().windowInsetsPadding(WindowInsets.safeDrawing)) {
        CMS.Navigation.CapsuleNavigation(
            labels = listOf("记录", "工具"),
            selectedIndex = pager.currentPage,
            onSelectedChange = { scope.launch { pager.animateScrollToPage(it) } },
            pageProgress = pager.currentPage + pager.currentPageOffsetFraction
        )
        CMS.Content.Pager(pager, Modifier.weight(1f)) { page ->
            CMS.Content.Page(
                topInset = 0.dp,
                topBarReserve = 12.dp,
                bottomReserve = 24.dp,
                springOverscroll = true,
                topBar = {}
            ) {
                CMS.Content.Section {
                    repeat(24) { index ->
                        CMS.Content.ListRow(
                            "第 ${page + 1} 页 · 内容 ${index + 1}",
                            showChevron = false
                        ) {}
                    }
                }
            }
        }
    }
}
```

| 接入规则 | 原因 |
| --- | --- |
| Pager + Page 自动连接每页主滚动 | 宿主无需维护桥列表 |
| 一个页面只有一个主滚动桥 | 多个独立滚动区应明确分流 |
| 默认 respectConsumedGestures = false | 子层消费不阻止统一父级仲裁 |
| 专用拖动控件用 canStart 排除 | 保留滑杆、文本选择、地图等自己的操作 |
| 统一读取 PagerState | 点击、手势和程序切页共享状态 |
| 已有外层 Source 时关闭重复采样 | Pager 和内部滚动无需重复创建原生边界 |
| 原生 Pager 适配 | 仅作为高级接入，原生 userScrollEnabled 必须关闭 |

抬手后重新按下会停止旧动量并重新判断方向，`allowAxisChange` 只影响按住期间的换向。详细契约见 [Page](components/Page.md) 和 [触控优先级](components/TouchPriority.md)。

## 6.1 自定义采样骨架

需要自行组织固定玻璃层时使用 Source：

```kotlin
Box(Modifier.fillMaxSize().background(PageBackground)) {
    // 1) 只包内容：玻璃采样源
    CMSGlassContentSource(Modifier.fillMaxSize(), hazeState = haze) {
        CMSScrollView(Modifier.fillMaxSize(), sampleGlassContent = false) {
            // 页面内容
        }
    }

    // 2) 顶栏：与采样源平级
    Row(Modifier.statusBarsPadding()) {
        CMSBackButton(onClick = onBack)
        Text("设置")
    }

    // 3) 悬浮玻璃控件、菜单
    CMSPopupMenu(
        hazeState = haze,
        items = items,
        currentIndex = current,
        anchorRect = anchor,
        visible = menuVisible,
        onSelect = { /* ... */ },
        onDismiss = { menuVisible = false }
    )
}
```

规则：

1. 玻璃控件不能位于自己的采样源内；
2. 一个页面只保留一个页面级采样源；
3. 长按类菜单优先放进独立 `Popup`，与采样树彻底隔离。

跨窗口菜单可通过 `CMSPopupMenu(samplingSource = source)` 显式指定原页面内容源，
`source` 由 `CMSGlassContentSource(onSourceReady = { source = it })` 获取。
原生采样采用屏幕坐标，并监听菜单窗口的绘制以跟随动画。

## 7. 震动接入

```kotlin
// 启动时绑定业务开关
CMSHaptics.enabled = state.hapticEnabled

// 或者全局替换实现
CMSHaptics.provider = object : CMSHapticsProvider {
    override fun perform(context: Context, kind: CMSHapticKind) {
        if (kind == CMSHapticKind.Click) Haptics.triggerKey(context)
        else Haptics.trigger(context)
    }
}
```

菜单悬停与返回历史长按统一走 `CMSHaptics`；开关和滑块由宿主选择反馈时机。
模块接入时 VIBRATE 权限自动合并，源码接入时需在宿主 manifest 声明。
完整接口与迁移说明见 [`04-触感与宿主接口.md`](04-触感与宿主接口.md)。

## 8. 返回历史接入

```kotlin
object AppBackHistory : CMSBackHistory {
    override fun previous(context: Context) =
        PageBackHistory.previous(context).map { CMSBackDestination(it.id, it.label) }

    override fun returnTo(context: Context, id: String) = PageBackHistory.returnTo(context, id)

    override fun updateTitle(context: Context, title: String) =
        PageBackHistory.updateTitle(context, title)
}
```

通过 `CMSTheme(backHistory = AppBackHistory)` 或 `LocalCMSBackHistory` 提供。
未提供时 `CMSBackButton` 长按无动作，短按照常返回。

## 9. 原生引擎（CLEAR Motion Pro）

1. `native/jniLibs/<abi>/libCLEARMotionPro.so` → `app/src/main/jniLibs/<abi>/`；
2. `native/clearmotion_jni_bridge.cpp`、`CMakeLists.txt` → `app/src/main/cpp/`；
3. 配置 `externalNativeBuild { cmake { path = file("src/main/cpp/CMakeLists.txt") } }`。

详见 [`02-CLEAR-Motion.md`](02-CLEAR-Motion.md)。

## 10. 注意事项

- **包名**：组件为 `com.lindicra.cms`，模块接入时资源由库 namespace 提供，宿主不必改包名。
  仅手动源码复制时需要调整资源导入并同时复制主题、字体、图标和原生配置。
- **可选组件**：`optional/CMPlayerBackground.kt` 不参与默认编译。
- **16KB 页对齐**：JNI 链接参数已配置 16384，随附 arm64 引擎 LOAD 对齐为 `0x4000`。
- **许可**：`modules/*` 各自带 `LICENSE`；CLEAR Motion Pro 见 `native/licenses/`。
- **升级方式**：模块接入时同步完整库目录与依赖配置；源码接入时同时更新组件和主题，
  并按 [`04-触感与宿主接口.md`](04-触感与宿主接口.md) 核对触觉与返回历史。
