# 04 · 触感与宿主接口（v1.1.0）

1.1.0 起，组件不再直接依赖宿主的震动实现或页面栈。所有跨组件能力收口到两个接口：

| 接口 | 作用 | 提供方式 |
| --- | --- | --- |
| `CMSHaptics` / `CMSHapticsProvider` | 统一震动反馈 | 全局单例 + Compose Local |
| `CMSBackHistory` | 返回按钮长按历史 | Compose Local |

---

## 1. 统一震动接口 `CMSHaptics`

### 1.1 类型

```kotlin
enum class CMSHapticKind {
    Tick,       // 普通界面反馈（轻），对应系统 EFFECT_TICK
    Click,      // 键盘按键反馈（略重），对应系统 EFFECT_CLICK
    LongPress   // 长按确认，默认同样使用 EFFECT_TICK
}

fun interface CMSHapticsProvider {
    fun perform(context: Context, kind: CMSHapticKind)
}
```

### 1.2 默认实现

`CMSDefaultHapticsProvider` 使用系统震动效果，并为较旧系统提供单次震动：

| Kind | Android Q+ | Android 8–9 |
| --- | --- | --- |
| `Tick` / `LongPress` | `EFFECT_TICK` | `createOneShot(20ms, 150)` |
| `Click` | `EFFECT_CLICK` | `createOneShot(25ms, 220)` |

无振动器或调用失败时静默返回，不抛异常。

`cms-core` 的 manifest 已声明 `android.permission.VIBRATE`，模块接入时自动合并。
按源码复制接入时，宿主需自行声明该权限；它是普通权限，无需运行时授权。

### 1.3 全局入口

```kotlin
object CMSHaptics {
    var provider: CMSHapticsProvider   // 默认 CMSDefaultHapticsProvider
    var enabled: Boolean               // 默认 true
    fun trigger(context: Context, kind: CMSHapticKind = CMSHapticKind.Tick)
}
```

View、原生代码、协程里都可以直接调用：

```kotlin
CMSHaptics.trigger(view.context, CMSHapticKind.Click)
```

### 1.4 Compose 局部覆盖

```kotlin
val LocalCMSHaptics = staticCompositionLocalOf<CMSHapticsProvider?> { null }
val LocalCMSHapticsEnabled = staticCompositionLocalOf { true }

@Composable
fun rememberCMSHaptic(): (CMSHapticKind) -> Unit
```

`rememberCMSHaptic()` 的判定顺序：

1. `LocalCMSHapticsEnabled` 与 `CMSHaptics.enabled` 必须同时为 `true`；
2. 优先使用 `LocalCMSHaptics`，未提供时使用 `CMSHaptics.provider`；
3. 任何异常都被捕获，不会影响交互。

### 1.5 宿主接入示例

**绑定业务开关（设置里的“震动触感”）**

```kotlin
// 应用启动或设置变化时
CMSHaptics.enabled = settings.hapticEnabled
```

**替换为宿主自己的震动实现**

```kotlin
CMSHaptics.provider = object : CMSHapticsProvider {
    override fun perform(context: Context, kind: CMSHapticKind) {
        when (kind) {
            CMSHapticKind.Click -> Haptics.triggerKey(context)
            else -> Haptics.trigger(context)
        }
    }
}
```

**只在某个页面关闭震动**

```kotlin
CompositionLocalProvider(LocalCMSHapticsEnabled provides false) {
    SettingsContent()
}
```

**在组件内触发**

```kotlin
val haptic = rememberCMSHaptic()
IconButton(onClick = { haptic(CMSHapticKind.Tick); onBack() }) { /* ... */ }
```

### 1.6 组件内的触发点

| 组件 | 时机 | Kind |
| --- | --- | --- |
| `CMSPopupMenu` / `CMSMenuTouchState` | 悬停/切换到某个菜单项 | `Tick` |
| `CMSBackButton` | 长按成功弹出返回历史 | `LongPress` |
| `CMSSwitch` | 由宿主决定（组件本身不主动震动） | — |

菜单悬停与返回历史长按使用统一接口。其他业务动作可由宿主按需触发，接入前应核对组件自带反馈，避免重复震动。

## 2. 返回历史接口 `CMSBackHistory`

### 2.1 类型

```kotlin
data class CMSBackDestination(
    val id: String,      // 宿主路由/页面标识
    val label: String    // 菜单展示标题
)

interface CMSBackHistory {
    fun previous(context: Context): List<CMSBackDestination>  // 最新的在前
    fun returnTo(context: Context, id: String)
    fun updateTitle(context: Context, title: String)
}

val LocalCMSBackHistory = staticCompositionLocalOf<CMSBackHistory?> { null }
```

### 2.2 行为

- `CMSBackButton` 短按始终执行 `onClick`；
- 长按时调用 `previous()`，列表非空才弹出菜单并触发 `LongPress` 震动；
- 选择后调用 `returnTo(id)`；由宿主决定是 `finish()` 中间页面还是重建栈；
- 未提供 `LocalCMSBackHistory` 时长按无动作，不影响短按返回。

### 2.3 宿主实现示例

```kotlin
object AppBackHistory : CMSBackHistory {

    override fun previous(context: Context): List<CMSBackDestination> =
        PageBackHistory.previous(context)
            .map { CMSBackDestination(it.id, it.label) }

    override fun returnTo(context: Context, id: String) {
        PageBackHistory.returnTo(context, id)
    }

    override fun updateTitle(context: Context, title: String) {
        PageBackHistory.updateTitle(context, title)
    }
}
```

在主题或页面根部提供：

```kotlin
CMS.Interaction.BackHistory(AppBackHistory) {
    CMS.Appearance.Theme { AppContent() }
}
```

`CMSTheme(backHistory = AppBackHistory)` 也可以直接传入。`CMS.Appearance.Theme` 默认继承外层历史作用域；直接使用 `CompositionLocalProvider` 仍兼容。

此体验统一命名为“返回历史 · Back History”，在交互分类单列。完整教程和可运行的多级案例见 [返回历史](components/BackHistory.md)。

### 2.4 标题同步

二级页在标题变化时调用：

```kotlin
val history = LocalCMSBackHistory.current
SideEffect { history?.updateTitle(context, title) }
```

这样长按菜单里展示的始终是页面最新标题。

## 3. 迁移清单（1.0 → 1.1.0）

| 1.0 写法 | 1.1.0 写法 |
| --- | --- |
| 组件内 `vibrator.vibrate(...)` | `CMSHaptics.trigger(context, kind)` |
| 组件内读取业务 `hapticEnabled` | `CMSHaptics.enabled` 或 `LocalCMSHapticsEnabled` |
| 返回按钮写死页面栈 | 提供 `LocalCMSBackHistory` |
| `CMSGlassBackButton(onClick = onBack, iconColor = color)` | `CMSBackButton(onClick = onBack, iconColor = color)`；旧接口保持可用 |
| `cms/optional/CMSPlayerBackground` | 移到 `optional/`，按需复制 |
